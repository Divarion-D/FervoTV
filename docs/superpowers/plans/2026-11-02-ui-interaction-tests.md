# UI Interaction Tests Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** автоматически проверять дизайн в действии: сенсорные жесты, управление пультом на TV, фокус, раскладку и переходы между экранами Fervo TV.

**Architecture:** расширить существующие Compose/Robolectric-тесты быстрыми проверками компонентов; сквозные сценарии запускать как instrumented-тесты настоящего приложения на телефонном и TV Android. Сенсорные события и клавиши проходят через UI, не через прямые вызовы обработчиков. Семантика и геометрия дают автоматические assertions, снимки до/после действия — материал для визуальной проверки.

**Tech Stack:** Kotlin, JUnit4, существующие Compose UI Test/Robolectric; AndroidJUnitRunner и UI Automator для устройства/эмулятора; текущие синтетические медиаданные из `tools/p3-synthetic-streams.sh`.

**Spec:** [UI и навигация](../../spec/30-ui-navigation.md), [дизайн](../../spec/33-design.md), [плеер](../../spec/15-player.md), [текущая приёмка P3](../../P3_PLAYER_DEVICE_CHECKS.md).

**Задача:** QA-UI-001. **Статус:** ⬜ запланировано, реализация этого плана не начата. Существующие 10 регрессий `VodControlsTest` — исходная база, а не выполнение всего плана. Это сквозная техническая задача P0–P3, не новая пользовательская функция из перечня 222 функций.

## Global Constraints

- Тестируется универсальное приложение `app-tv`; устаревший `app-mobile` не включается в новую UI-матрицу.
- `minSdk = 21`, `compileSdk = 35`, `targetSdk = 35`, JDK 17; Compose BOM остаётся `2024.12.01`. Не обновлять runtime-зависимости ради тестов.
- Инструментальный прогон использует отдельный пакет `io.github.divarion_d.fervotv.uitest`, не release и не пользовательский debug. Сброс/наполнение тестовой БД разрешён только внутри этого пакета.
- Только синтетические источники и локальный медиасервер: никаких IPTV-реквизитов, внешнего интернета, установки обновлений и реальных пользовательских копий в тестах/артефактах.
- Узкий/широкий каркас проверяется на границе 600 dp. Зона касания — не меньше 48×48 dp. TV 960×540 dp: безопасные поля 48 dp по бокам, 24 dp сверху/снизу; исключение для свёрнутого меню — по спецификации.
- Панель плеера: один ряд горизонтально, два в портрете. Фокус и выбранный элемент — разные состояния; OK активирует именно элемент в фокусе.
- Не менять дизайн для совпадения с текущим ошибочным снимком. Новые эталоны и расхождения со спецификацией требуют просмотра; не обновлять эталоны автоматически.
- Коммит, push и запуск на личном устройстве — только по отдельному разрешению владельца. Данный план их не разрешает.

## Review Focus

1. Клавиши с поверхности видео не входят в панель, хотя тест с принудительным фокусом проходит — задачи 2 и 4.
2. Долгий OK открывает меню и его отпускание случайно запускает первый пункт — задачи 2 и 3.
3. Превью перекрывает списки или остаётся поверх полноэкранного плеера — задачи 3 и 4.
4. Back/закрытие клавиатуры/поворот теряют фокус, позицию или открывают боковое меню — задачи 3 и 4.
5. Длинный текст, крупный шрифт, пустой список или скрытый элемент ломают раскладку и доступность действий — задачи 3 и 5.

## Матрица запусков

| Среда | Ввод | Что подтверждает |
| --- | --- | --- |
| Host Compose/Robolectric: port/land, normal/television | Touch и key injection отдельными тестами | Поведение компонентов и регрессии; не аппаратный TV |
| Телефонный Android-эмулятор, портрет и горизонтально | Тап, удержание, свайп, drag, Back | Настоящую сенсорную цепочку и адаптивный UI |
| Android TV-эмулятор, горизонтально | DPAD, OK, Back, Menu, медиаклавиши, повторы | TV UI-режим и сквозной путь пульта без касаний |
| Физический TV/приставка | Те же инъекции клавиш через instrumentation/ADB, затем smoke аппаратным пультом | Поведение на целевом устройстве; доставку IR/Bluetooth проверяет только физический пульт |

Основные конфигурации: телефон 360×800 dp / 800×360 dp; широкий экран 800×1280 dp; TV 960×540 dp. Для каркаса отдельные host-проверки ширины 599/600/601 dp. Базовый CI-образ Android API 35 фиксируется вместе с density, locale, font scale и настройками анимаций. Дополнительные варианты: ru/en и fontScale 1.0/1.3. Не размножать каждый сценарий на всё декартово произведение: основные маршруты — на телефоне и TV, типографика — отдельной матрицей задачи 5.

Релизный manifest и данные `core` не менять.

- [ ] Добавить тесты `seedRejectsNonTestPackage` и `seedIsRepeatable`: повторное наполнение даёт те же стабильные ID, порядок и историю без дублей.
- [ ] Добавить build type `uiTest`, `initWith(debug)`, suffix `.uitest`, `matchingFallbacks += "debug"`, `testBuildType = "uiTest"` и `AndroidJUnitRunner`. Подключить общий каталог к `testDebug` и `androidTest`; новые инструментальные зависимости — только `androidTestImplementation`.
- [ ] Подготовить небольшой набор: категории, длинные/одинаковые названия, отсутствующий логотип/постер, достаточно строк для прокрутки, фильм с прогрессом, сериал с двумя сезонами, EPG с фиксированным временем. Состояния loading/empty/error задаются явно, не случайным обрывом интернета.
- [ ] Для реального движка использовать локальные HLS/MP4 из существующего генератора; в эмуляторе — адрес хоста, на устройстве — проверенное ADB reverse/локальное соединение. Сервер запускается и останавливается самим тестовым workflow.
- [ ] Проверить `:app-tv:testDebugUnitTest` и `:app-tv:connectedUiTestAndroidTest` с фильтром `app.iptvplayer.UiHarnessTest`; PASS, повторяемые данные, release/debug пользователя не затронуты. Проверить, что `:app-tv:assembleRelease` не включает тестовые классы/зависимости.

## Задача 2. Контракты двух способов ввода

**Files:** создать `app-tv/src/testDebug/java/app/iptvplayer/InputInteractionTest.kt`, `app-tv/src/androidTest/java/app/iptvplayer/InputDeviceTest.kt`. При необходимости добавить стабильные `testTag` только на неоднозначные контейнеры существующих экранов; не создавать тестовую копию UI.

**Interfaces:** узлы ищутся по стабильной семантике/ID, координаты жеста вычисляются из текущих bounds. На TV тест начинается с начального фокуса приложения, а не `RequestFocus` на желаемой кнопке.

- [ ] Написать `touchTapActivatesOnce`, `touchLongPressOpensMenuWithoutActivation`, `swipeScrollsList`, `dragSeeksOnRelease`: использовать `performTouchInput`, а не только семантический `performClick`.
- [ ] Написать `remoteStartsWithVisibleFocus`, `remoteArrowsMoveWithoutActivation`, `remoteOkActivatesFocusedItemOnce`, `longOkReleaseDoesNotSelectMenuItem`, `heldArrowRepeatsWithoutOpeningWindows`.
- [ ] Для Compose отправлять KeyDown/KeyUp, удержание/повторы через время событий; после действий, меняющих экран или раскладку, разделять инъекции ожиданием UI. Не подменять повторы одним изменением `MainTestClock`.
- [ ] В device-проверке долгого OK передавать реальную последовательность down → repeat с `FLAG_LONG_PRESS` и ненулевым `repeatCount` → up, сохраняя `downTime`; серия одиночных `pressDPadCenter` не заменяет удержание.
- [ ] На TV-устройстве повторить ввод через Android key events/UI Automator: DPAD вверх/вниз/влево/вправо, CENTER, BACK, MENU, PLAY_PAUSE, CH± и цифры там, где они поддержаны. Никаких касаний и прямых `onClick` в TV-маршрутах.
- [ ] Проверять эффект и отсутствие лишнего эффекта: изменился фокус, но не канал/позиция видео; OK открыл ровно один экран; долгое нажатие не равно одиночному.
- [ ] Прогнать обе группы `InputInteractionTest` и `InputDeviceTest`; каждый известный дефект сначала воспроизвести красным тестом, исправлять минимально в общей цепочке ввода, затем получить PASS.

## Задача 3. Сквозные маршруты экранов

**Files:** создать в `app-tv/src/androidTest/java/app/iptvplayer/` файлы `NavigationUiTest.kt`, `LiveGuideUiTest.kt`, `LibrarySearchHistoryUiTest.kt`, `SettingsUiTest.kt`. Целевые production-файлы: `MainActivity.kt`, `ui/Sections.kt`, `HomeScreen.kt`, `LiveScreen.kt`, `GuideGrid.kt`, `LibraryScreen.kt`, `SearchScreen.kt`, `MoreScreen.kt`, `SettingsScreen.kt`; менять их только для минимальной семантики или воспроизведённой ошибки.

**Interfaces:** каждый сценарий имеет touch- и remote-вариант над одним набором `UiFixtures`. Совпадать должен пользовательский результат, а не число/направление шагов разных раскладок.

| Набор | Обязательные действия и assertions |
| --- | --- |
| NavigationUiTest | Главная → Эфир → Телегид → Фильмы → Сериалы → Поиск → История → Настройки; раздел доступен, выбранное состояние верно; Back возвращает к исходному элементу. При отключённой главной стартует Эфир. |
| LiveGuideUiTest | Категория → канал → превью → полный экран → Back; списки не исчезают, превью не перекрывает плеер, не открывается боковое меню. Фокусная полоса соответствует строке и ID канала, который активирует OK. Проверить прокрутку, границы категорий/каналов/EPG и контекстное меню. |
| LibrarySearchHistoryUiTest | Каталог → фильм/эпизод → продолжить → Back; поиск по всем типам ведёт к правильному ID; история/продолжение сохраняют позицию, фокус и прокрутку. Пустой результат не оставляет невидимый фокус. |
| SettingsUiTest | Группа → строка → выбор/редактор → Back; возврат на ту же строку. Вход фокуса в текстовое поле не открывает IME; OK/тап открывает, Back закрывает IME, потом страницу. Долгий OK/касание не запускают лишнее действие. |

- [ ] Написать перечисленные сценарии, включая loading/empty/error, скрытые элементы и возврат из шторки. Имена тестов содержат сценарий и способ ввода.
- [ ] Проверить порядок закрытия верхнего слоя и отсутствие событий в нижнем экране; проверять не только финальный экран, но и последовательность состояний после Back. Для кратких вспышек бокового меню сохранять трассу состояний/видеозапись — один конечный снимок их не исключает.
- [ ] Выполнить `:app-tv:connectedUiTestAndroidTest` на телефонном и TV-эмуляторе с фильтром этих классов. PASS отдельно для touch и remote; ожидаемое падение по отсутствующей функции записывается как незавершённый критерий, а не скрывается `@Ignore`.

## Задача 4. Плеер, слои и возврат фокуса

- [ ] Повторить device-маршрут превью → полный экран → Back для обоих способов ввода. Проверять владельца видеоповерхности и факт воспроизведения; Compose-снимок без `SurfaceView` не является доказательством отсутствия видео поверх другого слоя.
- [ ] Прогнать оба host-класса и `PlayerInteractionUiTest` на телефоне/TV. Ожидать PASS; отдельно зафиксировать, какие проверки выполнялись с fake engine, а какие с реальным.

## Задача 5. Дизайн после взаимодействия

**Files:** создать `app-tv/src/androidTest/java/app/iptvplayer/DesignInteractionUiTest.kt`, `app-tv/src/androidTest/java/app/iptvplayer/UiGeometryAssertions.kt`; создать `docs/UI_INTERACTION_CHECKS.md` для результатов и визуальной приёмки.

**Interfaces:** `assertTouchTarget(node: SemanticsNodeInteraction, minSize: Dp)` проверяет фактическую цель касания; `assertInside(node: SemanticsNodeInteraction, container: SemanticsNodeInteraction)` проверяет видимые bounds. Не требовать отсутствия любых пересечений: разрешённые меню поверх контента и подписи/контейнеры исключаются явно.

- [ ] Написать `controlsStayReachableAfterInteraction`, `focusedItemMatchesActivatedItem`, `touchTargetsAtLeast48Dp`, `longTextAndFontScaleKeepActionsVisible`, `widthBoundaryKeepsNavigationReachable`.
- [ ] Проверять до/после действия размеры, положение, видимость, scroll-to-focus и отсутствие недопустимого clipping/перекрытия соседних действий. Отдельно проверять фокус, выбранное и нажатое состояния; не считать оранжевую центральную кнопку плеера признаком фактического фокуса.
- [ ] Зону касания подтверждать также pointer-событиями у границ hit area, а не размером рисунка иконки; касание за пределами зоны не активирует соседнее действие.
- [ ] В ru/en и fontScale 1.0/1.3 проверить длинные названия, пустые/ошибочные состояния, панели и диалоги; на TV — safe area и увеличение карточки без перекрытия соседей; на touch — отсутствие TV-подсказок и доступность жестов.
- [ ] На фиксированных checkpoint после тапа, фокуса, прокрутки, OK/Back, поворота и открытия меню сохранять снимки с ID сценария и конфигурацией. Стабилизировать время/данные и анимации; видеокадр не использовать как эталон UI.
- [ ] Сверить снимки с `33-design.md` и согласованными примерами; отметить найденные расхождения отдельно от функционального PASS. Попиксельный golden-gate не входит в первую реализацию: автоматическая часть проверяет геометрию/состояния, оформление подтверждается просмотром снимков. Не выдавать её за полную автоматическую оценку дизайна.
- [ ] Прогнать `DesignInteractionUiTest`, получить PASS автоматических assertions и отдельный результат визуальной приёмки, не смешивая эти статусы.

## Готовность и порядок выполнения

Порядок: 1 → 2 → 3 → 4 → 5 → 6. Самые ранние регрессии — вход фокуса с видео, категории/каналы, наложение превью и Back. Для новых дефектов: красный тест → минимальное исправление → зелёный тест → проверка соседнего способа ввода.

Задача закрывается после готовности двух способов ввода, прогона матрицы основных экранов, публикации отчётов CI и отдельно указанного результата визуальной/физической TV-приёмки. Если последний прогон недоступен, задача остаётся 🟡. Уже найденное падение CI производительности каталога не считается исправленным этим планом.
