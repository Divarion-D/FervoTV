# 15. Плеер (PLR)

Полноэкранное воспроизведение эфира, архива, фильмов и эпизодов. Устройство движков — `01-architecture.md`, §6.

### PLR-001 Базовое воспроизведение
- **Суть:** HLS, MPEG-TS и MP4 через Media3 ExoPlayer.
- **Критерии приёмки:**
  - тип определяется по расширению; ссылка без расширения, не открывшаяся как файл, один раз пробуется как HLS;
  - отставание от окна эфира — автоматический возврат к эфиру;
  - прочие ошибки — текст в плеере, OK повторяет попытку.
- **Фаза:** P0
- **Статус:** ✅ есть (HLS, MPEG-TS, MP4, MKV/DTS, DASH и поток без расширения проверены на телефоне по видео; звук MP2/DTS ограничен PLR-012; буферизация без прогресса `Defaults.BUFFER_STALL_TIMEOUT_MS` — ошибка с повтором)

### PLR-002 Жизненный цикл
- **Суть:** плеер ведёт себя как приложение для ТВ: не гаснет экран, не перезапускается поток.
- **Критерии приёмки:**
  - экран не гаснет во время воспроизведения;
  - при уходе в фон — пауза (для эфира — освобождение потока), при возврате — продолжение (эфир — с текущего момента);
  - поворот экрана не перезапускает поток.
- **Фаза:** P0
- **Статус:** ✅ есть (04.11.2026 на телефоне: во время воспроизведения установлен `KEEP_SCREEN_ON`; VOD при выключенном экране ставится на паузу с неизменной позицией и продолжается после возврата, в PiP продолжает играть без сброса позиции; live при выключенном экране останавливается и закрывает соединение с сервером, после возврата воспроизводится из нового окна динамического HLS; поворот экрана не сбрасывает позицию VOD. Host-тесты PlayerSession и TV UI проходят.)

### PLR-003 Инфо-плашка
- **Суть:** при переключении канала и по OK/Info на несколько секунд появляется плашка с логотипом, номером и названием.
- **Пульт:** OK, Info, Menu, Guide. **Сенсор:** тап.
- **Критерии приёмки:**
  - время показа — из `Defaults`;
  - с P1 на плашке — передачи «до / сейчас / далее» (EPG-006).
- **Фаза:** P0
- **Статус:** ✅ есть (без телегида)

### PLR-004 Интерфейс движка воспроизведения
- **Суть:** экраны управляют воспроизведением через интерфейс ядра, а не через ExoPlayer напрямую.
- **Критерии приёмки:**
  - текущее поведение PLR-001…003 сохранено после перехода на интерфейс;
  - один сеанс воспроизведения переживает переход «превью → весь экран → плеер в углу» без перезапуска потока;
  - есть тестовая реализация движка для unit-тестов логики плеера.
- **Фаза:** P0
- **Статус:** ✅ есть (02.11.2026: контракт PlaybackEngine/PlayerSession подтверждён PlayerSessionTest — один лениво созданный движок, повторное открытие без перезапуска, смена SurfaceView и корректное освобождение; переходы между экранами и плеер в углу проверены на телефоне ранее; отдельная TV-проверка интерфейса ядра не требуется)

### PLR-005 Запасные варианты и время отказа
- **Суть:** неоткрывшийся поток перебирает варианты: другой формат (HLS ↔ MPEG-TS) и другой движок, каждый по разу.
- **Сценарий:** канал не открылся в ExoPlayer — через пару секунд он играет в запасном движке, пользователь ничего не нажимал.
- **Критерии приёмки:**
  - общее время перебора ограничено настройкой «Сдаться через»: 15 / 30 / 60 с / никогда, по умолчанию 30 с; ожидания, которые просит сам провайдер, не считаются;
  - по исчерпании — понятное сообщение и запись в журнал (PLR-025), а не вечный спиннер;
  - удачный вариант для канала эфира запоминается; для фильмов не запоминается — каждый фильм стартует с выбранного движка;
  - если канал часто теряет кадры, плеер предлагает попробовать другой движок.
- **Фаза:** P3
- **Статус:** 🟡 частично (ограничены время и число попыток, перебираются DASH/HLS/progressive, ошибка журналируется, рабочий формат эфира запоминается; второго движка и предложения сменить его при потерях кадров нет — PLR-017/018)

### PLR-006 Восстановление при обрыве
- **Суть:** при обрыве эфира плеер сам переподключается.
- **Критерии приёмки:**
  - при остановке потока остаётся последний кадр; через ~10 с — сообщение о потере сигнала и о том, что идёт повторное подключение;
  - повторы с нарастающей паузой, число попыток — настройка;
  - картинка возвращается сама, когда сеть восстановилась;
  - при отказе провайдера из-за лимита подключений — обратный отсчёт и автоповтор (SRC-022).
- **Фаза:** P3
- **Статус:** 🟡 частично (эфир переподключается с backoff и ограничением времени/попыток; stall определяется без вечного спиннера, `Retry-After` провайдера показывает обратный отсчёт и не расходует окно «сдаться через». Сохранение последнего кадра и полная экранная индикация требуют аппаратной проверки)
- **Проверка ТВ 03.11.2026:** ✅ После точно ограниченного 12-секундного HTTP 503 HLS возобновился без OK. Более длинный отказ исчерпал лимит; после восстановления сервера помог ручной OK. 🟡 Wi-Fi не отключался, специальное сообщение о переподключении на экране не показано, полная матрица backoff/лимитов не принята.

### PLR-007 Панель управления
- **Суть:** скрывающаяся панель с перемоткой и кнопками.
- **Пульт:** OK — показать/скрыть; Back — сначала скрыть панель, затем выйти; при скрытой панели у фильма ◀▶ — перемотка на шаг (удержание — непрерывно). **Сенсор:** тап — показать/скрыть, двойной тап по краю — перемотка на шаг.
- **Критерии приёмки:**
  - полоса перемотки с предпросмотром времени; предыдущий/следующий эпизод; пауза;
  - кнопки: аудио, субтитры, скорость (0,5–2×), масштаб и формат кадра (вписать, заполнить, растянуть, исходный, 16:9, 4:3), громкость и выключение звука, избранное, сведения о потоке, качество (если вариантов несколько);
  - часов на экране плеера нет (решение владельца, UI-009); при архиве время передачи — CU-007;
  - шаг перемотки — настройка (по умолчанию 10 с);
  - масштаб и громкость запоминаются для элемента; сброс — SET-009;
  - у каждой кнопки при фокусе видна подпись.
- **Фаза:** P3
- **Статус:** ✅ реализовано (панели эфира/VOD, пауза, шаг перемотки, скорость, масштаб, громкость/mute, избранное, дорожки, качество, сведения, таймер, audio-only и внешний плеер; масштаб и громкость запоминаются. Host UI проверяет навигацию и Back; физический пульт остаётся в финальной приёмке)
- **Проверка UI:** ✅ Раскладка проверена в эфире и VOD: один ряд горизонтально, два в портрете. Подтверждены пауза/продолжение и перемотка VOD ±10 с, меню и крестовина эфира в портрете. ✅ После исправления на телефоне в обеих ориентациях пройден вход фокуса с видео на кнопки VOD и маршрут к «Ещё» без перемотки; Back скрывает панель перед выходом. Возврат из меню проверен горизонтально, автоскрытие после OK на кнопке — в портрете. 🟡 Полный набор команд, все переходы фокуса и аппаратный пульт не приняты. Подробности: [чеклист](../P3_PLAYER_DEVICE_CHECKS.md).
- **Проверка ТВ 03.11.2026:** ✅ Вход фокуса VOD, маршрут к «Ещё» без перемотки и кнопки ±10 с подтверждены. 🟡 Первый Back с кнопки на паузе только снимает фокус, следующий скрывает панель; нет подписей у горизонтальных кнопок. [Подробный отчёт](../P3_TV_DEVICE_CHECKS.md).
- **Последующее исправление:** ✅ Native Back с фокуса кнопки VOD скрывает панель одним нажатием в host TV-тесте API 25; следующий Back закрывает плеер. На физическом ТВ новый код ещё не принят; см. [roadmap](90-roadmap.md#p3-плеер).

### PLR-008 Аудиодорожки
- **Суть:** выбор звуковой дорожки на лету.
- **Критерии приёмки:**
  - у дорожки — язык, кодек, число каналов;
  - переключение без перезапуска потока.
- **Фаза:** P3
- **Статус:** ✅ есть (03.11.2026 на физическом ТВ проверены две реальные AAC-дорожки ru/en: язык, кодек, число каналов и выбранное состояние отображаются; смена на паузе сохранила 8421 мс, а во время воспроизведения — playing и продолжающуюся позицию 55397 → 99377 мс без сброса. Пользователь подтвердил звук после выбора en. Поддержка DTS/FFmpeg оценивается отдельно в PLR-012, не переносится из этого теста.)

### PLR-009 Встроенные субтитры
- **Суть:** текстовые (SRT, ASS, WebVTT), графические (PGS, VobSub, DVB) и скрытые субтитры (CEA-608/708).
- **Критерии приёмки:**
  - все дорожки видны в выборе с языком; «Выключены» — отдельный пункт;
  - скрытые субтитры работают и в эфире.
- **Фаза:** P3
- **Статус:** 🟡 частично (выбор/выключение дорожек и реальный `SubtitleView` подключены через Media3; текстовые субтитры получают оформление PLR-010. Графические PGS/VobSub/DVB и CEA зависят от контейнера/декодера и ещё не приняты на устройстве)
- **Проверка ТВ 03.11.2026:** 🟡 Встроенная английская дорожка отмечена выбранной, но известный текст TX3G в кадре внутри времени cue не появился. Наличие строки выбора не подтверждает отображение субтитров.

### PLR-010 Оформление субтитров
- **Суть:** шрифт, размер, цвет, положение и подложка субтитров.
- **Критерии приёмки:**
  - вариант «как в файле» сохраняет авторское оформление;
  - если размер на разных движках выглядит по-разному, он хранится для каждого движка отдельно;
  - изменения видны сразу на примере.
- **Фаза:** P3
- **Статус:** ✅ реализовано для ExoPlayer (шрифт, размер, цвет, фон, положение и авторские стили сохраняются; экран настроек показывает живой пример. Отдельное значение для другого движка появится вместе с таким backend)

### PLR-011 Субтитры из файла и синхронизация
- **Суть:** подключение файла субтитров с устройства или USB и сдвиг субтитров во времени.
- **Пульт:** в меню субтитров строка сдвига: ◀▶ на 0,1 с, OK — обнулить.
- **Критерии приёмки:**
  - выбор файла без интернета и без учётной записи;
  - сдвиг применяется сразу; поиск субтитров в сети — META-008.
- **Фаза:** P3
- **Статус:** 🟡 частично (`OpenDocument`, SRT/WebVTT MIME, внешний URI и смещение в движке реализованы; отдельное управление смещением в меню и реальная USB/SAF-проверка на TV ещё не закрыты)
- **Проверка ТВ 03.11.2026:** 🟡 Локальный SRT выбран через одноразовый файловый менеджер, но приложение передало `text/vtt`: журнал показывает `Expected WEBVTT. Got 1`, воспроизведение завершилось ошибкой. USB и применение сдвига не приняты.
- **Последующее исправление:** ✅ Host UI-тест результата OpenDocument подтверждает правильный MIME SRT/WebVTT, включая общий тип документа и непрозрачный URI; неизвестный формат не передаётся WebVTT-парсеру. Реальный показ текста, USB и сдвиг остаются 🟡; см. [roadmap](90-roadmap.md#p3-плеер).

### PLR-012 FFmpeg-аудио для ExoPlayer
- **Суть:** программный декодер звука для форматов, которые устройство не декодирует само (DTS, TrueHD, иногда AC3/E-AC3).
- **Критерии приёмки:**
  - переключатель в настройках звука, по умолчанию выключен; включается и автоматически как шаг запасной цепочки (PLR-005);
  - фильм с DTS-дорожкой на устройстве без DTS-декодера играет со звуком.
- **Фаза:** P3
- **Статус:** ✅ есть (Media3 1.5.1 FFmpeg extension собран воспроизводимо для четырёх ABI с LGPL FFmpeg 6.0 и декодерами DTS/DTS-HD, TrueHD/MLP, AC3/E-AC3. При выключенном переключателе MediaCodec остаётся первым, а FFmpeg автоматически используется для неподдерживаемой дорожки как шаг PLR-005; при включённом FFmpeg получает приоритет. Настройка по умолчанию выключена, сохраняется и входит в backup)

- **Проверка PLR-012 на ТВ 03.11.2026:** 🟡 MKV/DTS показывает картинку и playing, но пользователь подтвердил отсутствие звука на обычном выходе ТВ. Программный FFmpeg-fallback не собран и этим прогоном не принят.
- **Проверка на телефоне 06.11.2026:** 🟡 при громкости 5/15 fullscreen-видео запустилось для 11/11 synthetic fixtures; для 9/11 Android создал активный `AudioTrack` 48 кГц на speaker с ненулевым mixer gain. MPEG-TS/MP2 и MKV/DTS показывают видео, но не создают `AudioTrack`; в системных MediaCodec declarations TECNO CH6i нет MPEG Layer II/DTS decoder. Громкость после прогона возвращена к исходным 0/15. Это подтверждает необходимость software decoder, но не закрывает ручную проверку слышимости.
- **Проверка реализации 07.11.2026:** ✅ AAR собран из точных тегов Media3 1.5.1 и FFmpeg n6.0 через NDK r26b: 4 ABI, API 21, 16 KiB ELF alignment, только 5 заявленных audio decoders, SHA-256 `e7c1feda07ae6ee3f00e881daceb5952a8a577e9a5cdddfa0e153aa42e72394a`. ✅ 18 целевых core-тестов и 12 host UI-тестов прошли без ошибок; minified release APK собран, R8 сохранил FFmpeg renderer и все четыре native ABI. 🟡 Это не доказывает слышимый DTS на устройстве без DTS-декодера; физический MKV/DTS прогон нового APK ещё обязателен.
- **Техническая проверка на устройстве 07.11.2026:** 🟡 TECNO CH6i, API 33, без DTS MediaCodec: synthetic MKV/DTS (DCA 48 кГц mono, 768 кбит/с, SHA-256 `446abd7bc64f158d170248f4ed8c1c515abad767f8b86b1bfd7d88a8c010e7da`) воспроизведён при выключенном и включённом переключателе. Оба прогона дали playing, PCM16 `AudioTrack` 48 кГц mono на `SPEAKER`, ненулевой mixer/device gain и 0 underruns; в MediaCodec metrics был только video `c2.mtk.avc.decoder`, decoder/audio errors отсутствовали. HTTP fixture отвечал 200/206. Финальный debug APK дополнительно проверен переключением ON→OFF без перезапуска процесса (PID `17189` сохранился): настройка сразу стала `false`, `AndroidRuntime` crash log пуст. Переключатель и громкость `0/15` восстановлены. Телефон не заменяет TV-приёмку, человеческое акустическое подтверждение отдельно не записывалось.

### PLR-013 Предпочитаемые языки
- **Суть:** язык звука и субтитров выбирается автоматически.
- **Критерии приёмки:**
  - настройка профиля: список языков; для звука дополнительно «язык оригинала» (по TMDB, иначе основная дорожка);

- **Фаза:** P3
- **Статус:** 🟡 частично (предпочитаемые языки передаются Media3, ручной выбор звука/субтитров и «выключены» запоминается для элемента; выбор «языка оригинала» по TMDB ещё не реализован)

### PLR-014 Объёмный звук
- **Суть:** «Авто» / «Только стерео» / «Многоканальный», передача Dolby/DTS без декодирования.
- **Критерии приёмки:**
  - «Авто» пытается многоканальный вывод и при сбое вывода (тишина, ошибки, повторяющиеся опустошения буфера) переходит на стерео до конца сеанса, без перезапуска позиции;
  - переключатель «Передавать Dolby/DTS на ресивер»; при включённых ночном режиме или выравнивании звук декодируется в приложении.
- **Фаза:** P3
- **Статус:** ⬜ внешний блокер (надёжная проверка passthrough/fallback требует HDMI/ARC-ресивера и AC3/E-AC3/DTS fixtures; PCM DSP нельзя применять к закодированному bitstream)

### PLR-015 Громкость и обработка звука
- **Суть:** ночной режим (сжатие динамики), выравнивание громкости между каналами, усиление до 150% с мягким ограничителем, громкость по умолчанию.
- **Критерии приёмки:**
  - всё по умолчанию выключено; громкость по умолчанию 100%;
  - усиление выше 100% не даёт клиппинга на тестовом сигнале.
- **Фаза:** P3
- **Статус:** ✅ реализовано для PCM (громкость 0–150%, мягкий limiter, ночное сжатие и выравнивание по умолчанию выключены; DSP покрыт unit-тестами без клиппинга)

### PLR-016 Синхронизация звука
- **Суть:** сдвиг звука относительно картинки.
- **Пульт:** в меню звука ◀▶ с шагом 25 мс.
- **Критерии приёмки:**
  - «Запомнить для этого элемента»; общий сдвиг в настройках;
  - отдельная задержка для текущего устройства вывода (HDMI, ARC, Bluetooth, динамики ТВ, наушники) хранится для каждого вывода;
  - работает и при передаче звука без декодирования.
- **Фаза:** P3
- **Статус:** 🟡 частично (общий и запоминаемый для элемента сдвиг −500…+500 мс с шагом 25 мс реализован через PCM `AudioProcessor`; раздельные реальные output routes и passthrough требуют аппаратной матрицы)

### PLR-017 Смена движка для элемента
- **Суть:** кнопка на панели плеера переключает текущий канал или фильм на другой движок и запоминает выбор.
- **Сценарий:** канал заикается в ExoPlayer — одно нажатие, и он играет в альтернативном движке, в следующий раз тоже.
- **Критерии приёмки:**
  - кнопка показывает движок, который играет сейчас; скрыта, если альтернативный движок не собран или элемент защищён DRM;
  - выбор для элемента важнее общей настройки;
  - «Сбросить выбор движков» в настройках забывает все такие выборы.
- **Фаза:** P3
- **Статус:** ⬜ внешний блокер (в проекте собран только ExoPlayer; подключение libmpv/другого backend меняет ABI, APK, лицензирование и DRM-границы)

### PLR-018 Порядок движков
- **Суть:** для эфира и для видеотеки отдельно: «основной, затем запасной», «запасной, затем основной», «только основной», «только запасной».
- **Критерии приёмки:**
  - варианты «только» отключают автоматический переход;
  - переопределяется для отдельного источника (SET-010);
  - без собранного альтернативного движка настройка показывает только доступные варианты.
- **Фаза:** P3
- **Статус:** ⬜ внешний блокер (без второго playback backend порядок не имеет исполнимого смысла; варианты должны появиться вместе с одобренной альтернативой)

### PLR-019 Защищённые потоки (DRM)
- **Суть:** Widevine и ClearKey для DASH и HLS по данным из плейлиста (`#KODIPROP`: сервер лицензий или ключи `kid:key` прямо в плейлисте).
- **Критерии приёмки:**
  - пользователю ничего не нужно настраивать;
  - такие элементы всегда играют в ExoPlayer, не уходят во внешний плеер и не записываются (CU-014);
  - если устройство даёт только SD, это не считается ошибкой приложения;
  - источник, добавленный до поддержки DRM, получает ключи после обновления.
- **Фаза:** P3
- **Статус:** ✅ реализовано (Widevine/ClearKey из `#KODIPROP`, включая inline `kid:key`, сохраняются и передаются Media3; DRM скрывает внешний плеер. Реальная лицензия и уровень Widevine проверяются на устройстве)

### PLR-020 Определение контейнера по ответу
- **Суть:** формат потока определяется по объявленному типу, затем по фактическому содержимому ответа, затем по тому, что этот провайдер уже отдавал.
- **Критерии приёмки:**
  - DASH- и HLS-потоки без расширения в адресе играют;
  - для Xtream, где адрес не говорит о формате, используется тот же механизм.
- **Фаза:** P3
- **Статус:** ✅ реализовано (тип ответа используется первым; для неразмеченного/ошибочно размеченного потока ограниченно перебираются DASH, HLS и progressive без цикла. Решение покрыто `ExoRecoveryTest`; повторная матрица реальных потоков остаётся аппаратной приёмкой)

### PLR-021 Буферизация и сеть
- **Суть:** настройки для слабых каналов связи.
- **Критерии приёмки:**
  - «Задержка эфира» (близость к краю эфира) реально меняет размер буфера; «Предбуфер» — выкл / 2 / 5 / 10 с перед стартом;
  - для фильмов и архива: размер буфера, таймаут сети, число переподключений (варианты «авто»);
  - задержка, предбуфер и «сдаться через» переопределяются для источника.
- **Фаза:** P3
- **Статус:** 🟡 частично (минимальный/максимальный буфер, предбуфер, timeout/повторы сохраняются и применяются после пересоздания Repository; переопределение для отдельного источника относится к ещё не реализованному SET-010)

### PLR-022 Качество и декодирование
- **Суть:** аппаратное декодирование, программное выше 1080p по выбору, предпочтение SDR, максимальное качество, туннельный режим.
- **Критерии приёмки:**
  - аппаратное декодирование по умолчанию включено; при испорченной картинке — автоматический переход на программное;
  - 4K/8K без аппаратного декодера не запускается программно (если не включено явно) — понятная ошибка вместо зависания;
  - «Максимальное качество» ограничивает выбор варианта в адаптивном потоке; кнопка «Качество» выбирает вариант для текущего просмотра;
  - туннельный режим показывается только там, где декодер его поддерживает, и выключается после первого сбоя.
- **Фаза:** P3
- **Статус:** 🟡 частично (аппаратное декодирование остаётся стандартом Media3, глобальный предел высоты и выбор video track на текущий просмотр реализованы; автоматический software fallback, запрет UHD software и tunneling UI требуют decoder-capability реализации и hardware gate)

### PLR-023 Частота кадров и разрешение экрана
- **Суть:** по выбору экран переключается на частоту кадров видео; для фильмов — и на его разрешение.
- **Критерии приёмки:**
  - по умолчанию выключено; системная настройка Android TV о частоте важнее настройки приложения;
  - если поток не сообщает частоту, она измеряется и применяется, только если два замера совпали;
  - для фильмов: пауза на время переключения экрана (выкл–5 с) и совпадение разрешения, не выше родного у ТВ.
- **Фаза:** P3
- **Статус:** 🟡 частично (совпадение частоты передаётся ExoPlayer, фактический FPS принимается после двух согласованных замеров; пауза переключения и выбор разрешения ещё не реализованы, реальная смена display mode требует TV)

### PLR-024 Сведения о потоке
- **Суть:** экран с техническими данными текущего воспроизведения.
- **Критерии приёмки:**
  - кодеки, разрешение, частота кадров, глубина цвета, тип HDR, битрейт, декодер, звук, заполнение буфера, потерянные кадры, движок;
  - адрес потока показан со скрытыми логином и паролем;
  - измеряемые значения (фактический битрейт, кадры) — по настройке.
- **Фаза:** P3
- **Статус:** ✅ реализовано (кодеки, разрешение/FPS, SDR/HDR, глубина цвета, декодер, звук, буфер, dropped frames, фактический битрейт, движок и безопасный URL показаны; измеряемые метрики включаются отдельно. Реальный HDR/decoder output остаётся hardware acceptance)
- **Проверка ядра:** ✅ `PlaybackLogTest`: реквизиты Xtream в пути, userinfo, значения query, fragment, IPv6 и некорректные URL не раскрываются; используется та же функция маскирования, что и в новом окне.
- **Новые поля — проверка хоста:** ✅ 10 `VideoDetailsTest`: разбор метаданных без угадывания SDR/8/10 бит, неизвестные/несогласованные значения, жизненный цикл имени декодера. ✅ 5 `StreamDetailsUiTest`: показ, неизвестные значения, обновление открытого диалога, прокрутка горизонтально и русский перевод. Это не проверка реального HDR-вывода или декодирования на TV.
- **Проверка ТВ 03.11.2026:** ✅ Для HLS показаны SDR, 8 бит, 640×360, AAC и реальный `OMX.amlogic.avc.decoder.awesome`; URL замаскирован. Реальный HDR-вывод не принят: система не заявляет HDR-возможности экрана. Измеренный битрейт/потерянные кадры ещё отсутствуют.

### PLR-025 Журнал ошибок
- **Суть:** последний сбой приложения и история ошибок воспроизведения, переходов на запасные варианты и отказов.
- **Критерии приёмки:**
  - сбой пишется на диск в момент падения и виден после перезапуска;
  - экспорт в текстовый файл в папку загрузок, пароли и токены в адресах скрыты;
  - переключатель подробного журнала для воспроизведения проблемы.
- **Фаза:** P3
- **Статус:** 🟡 частично (ошибки, повторы и crash stack пишутся на диск с маскированием; экспорт и выключенный по умолчанию подробный режим добавлены. На Android scoped storage файл остаётся в app-scoped Download, а не в общей папке пользователя)
- **Проверка ТВ 03.11.2026:** ✅ DPAD/OK создали экспорт, проверено скрытие пути/userinfo всех его URL. Файл расположен в app-scoped `Android/data/<package>/files/Download`, не в общей папке Downloads. Last-crash и подробный режим не приняты.

### PLR-026 Картинка в картинке и плеер в углу
- **Суть:** системный PiP при выходе на главный экран ТВ/телефона; внутри приложения — плеер в углу, который продолжает играть при навигации.
- **Критерии приёмки:**
  - выбор другого канала обновляет плеер в углу на месте;
  - размер и угол — одна настройка;
  - субтитры видны и в уменьшенном окне;
  - к плееру в углу можно вернуться из любого экрана через пункт «Сейчас играет» бокового меню.
- **Фаза:** P3
- **Статус:** 🟡 частично (общий `PlayerSession` без перезапуска переносится в corner/«Сейчас играет», доступны возврат и Stop; системный PiP подключён с API 26. Настройка размера/угла и аппаратная PiP/OEM-проверка ещё не закрыты)

### PLR-027 Только звук
- **Суть:** пользователь выключает картинку и слушает, продолжая пользоваться приложением; элементы без видео (радио) помечаются, а не считаются ошибкой.
- **Критерии приёмки:**
  - в шапке — компактная плашка с названием, временем и кнопками «Во весь экран» / «Стоп»;
  - радиоканал показывает метку «только звук» вместо чёрного экрана с ошибкой.
- **Фаза:** P3
- **Статус:** 🟡 частично (видео отключается без остановки аудио, общий now-playing показывает название, «Во весь экран» и Stop при навигации; автоматическая метка radio-only по данным провайдера ещё не реализована)

### PLR-028 Таймер сна
- **Суть:** остановка воспроизведения через 15–90 мин, в конце передачи или в конце фильма/эпизода.

  - в конце эпизода по таймеру следующий эпизод не начинается;

- **Фаза:** P3

- **Проверка ядра:** ✅ `PlayerSessionTest`: остановка точно по дедлайну между секундными обновлениями, замена/отмена таймера, очистка таймера при закрытии перед открытием другого канала.

### PLR-029 Медиаклавиши и системная интеграция
- **Суть:** плеер работает с медиасеансом системы и аудиофокусом.
- **Критерии приёмки:**

  - уведомление другого приложения приглушает звук, а не ставит на паузу;
