# 32. Резервные копии, перенос, синхронизация и обновления (BAK)

### BAK-001 Резервная копия в один файл
- **Суть:** профили, источники, все настройки, правки категорий, избранное, история, позиции, привязки телегида, свои названия для TMDB, картинка фона и скачанные субтитры — в одном файле.
- **Сценарий:** перед сбросом приставки пользователь сохраняет копию на флешку.
- **Критерии приёмки:**
  - формат Fervo TV: ZIP-контейнер с расширением `.fervo`, внутри `manifest.json` (версия формата, версия приложения, дата, состав) и данные в JSON; формат версионируется и описан в `core` тестами — его читают и будущие клиенты других платформ;
  - пользователь выбирает, какие профили и части включить; профили с PIN экспортируются только после ввода PIN;
  - экран копии показывает, когда и куда была сохранена последняя копия.
- **Фаза:** P5
- **Статус:** ⬜ нет

### BAK-002 Шифрование копии
- **Суть:** необязательный пароль шифрует весь файл; без пароля секреты в файл не попадают.
- **Критерии приёмки:**
  - шифрование AES-256-GCM, ключ из пароля через PBKDF2 со случайной солью;
  - без пароля не сохраняются: пароли источников и прокси, MAC и идентификаторы порталов, ключи и логины сервисов, хэши PIN — и это сказано на экране;
  - неверный пароль при восстановлении — понятная ошибка, данные не меняются.
- **Фаза:** P5
- **Статус:** ⬜ нет

### BAK-003 Восстановление со слиянием
- **Суть:** восстановление добавляет данные к существующим, а не стирает их.
- **Критерии приёмки:**
  - перед применением — выбор частей; если снят выбор источников, — предупреждение, что каналов не будет;
  - формат файла определяется по содержимому, не по расширению;
  - все внутренние идентификаторы из файла переназначаются; источники совпадают по типу + адресу + логину (для Stalker — ещё MAC);
  - после восстановления восстановленные источники сразу начинают обновляться.
- **Фаза:** P5
- **Статус:** ⬜ нет

### BAK-004 Восстановление при первом запуске
- **Суть:** на шаге выбора способа начала мастера (UI-014) — «Восстановить из копии».
- **Критерии приёмки:**
  - приложение открывается только после полного окончания восстановления;
  - в поле пароля ▶ показывает введённые символы.
- **Фаза:** P5
- **Статус:** ⬜ нет

### BAK-005 Передача копии по сети
- **Суть:** копию можно отправить на ТВ с телефона или компьютера и забрать с ТВ через браузер — по механизму BAK-010.
- **Критерии приёмки:**
  - загрузка и скачивание файла через веб-страницу в локальной сети, защищённую PIN;
  - восстановление из пришедшего файла идёт по правилам BAK-003.
- **Фаза:** P6
- **Статус:** ⬜ нет

### BAK-006 Перенос на новое устройство
- **Суть:** новый ТВ забирает профили, источники, избранное, историю и позиции со старого по локальной сети — без облака, учётных записей и файлов.
- **Сценарий:** на старом устройстве «Ещё → Перенос и синхронизация» включает режим приёма запросов (пока открыт экран); новый находит его в сети, пользователь вводит 6-значный PIN старого, выбирает, что переносить, и видит, что изменится.
- **Критерии приёмки:**
  - устройство, которое настраивается, только принимает; на старом ничего не меняется;
  - обнаружение в локальной сети (mDNS/NSD); обмен зашифрован ключом, выведенным из PIN, учётные данные передаются только внутри зашифрованного канала;
  - протокол версионируется и описан тестами в `core`, чтобы клиенты других платформ могли его реализовать.
- **Фаза:** P5
- **Статус:** ⬜ нет

### BAK-007 Синхронизация ТВ и телефона
- **Суть:** обмен избранным, историей и позициями между `app-tv` и `app-mobile` по локальной сети.
- **Критерии приёмки:**
  - оба устройства должны открыть экран синхронизации; направление — отправить, принять или объединить;
  - перед применением — список изменений;
  - удаление на одном устройстве удаляет и на другом, а не возвращается при слиянии;
  - при конфликте позиции побеждает более свежая;
  - уже сопряжённое устройство не спрашивает PIN повторно и не появляется в списке дважды; одинаковые модели различаются коротким кодом.
- **Фаза:** P5
- **Статус:** ⬜ нет

### BAK-008 Без системной резервной копии
- **Суть:** автоматическое резервирование Android выключено; данные покидают устройство только через BAK-001, BAK-005–BAK-007.
- **Критерии приёмки:**
  - в манифесте выключены системный бэкап и перенос данных устройства;
  - на экране копии об этом сказано одной строкой.
- **Фаза:** P5
- **Статус:** ⬜ нет

### BAK-009 Обновления приложения
- **Суть:** проверка новой версии на GitHub Releases, просмотр изменений и установка прямо на ТВ.
- **Критерии приёмки:**
  - проверка вручную и по желанию при запуске;
  - перед установкой показывается журнал изменений новой версии;
  - скачивается APK, подходящий архитектуре устройства; при нехватке места — сообщение до скачивания;
  - установка через системный установщик с однократным запросом разрешения.
- **Фаза:** P6
- **Статус:** ⬜ нет

### BAK-010 Ввод с телефона по QR-коду
- **Суть:** общий механизм: ТВ поднимает веб-страницу в локальной сети и показывает QR-код и 6-значный PIN; на телефоне заполняется форма или выбирается файл.
- **Сценарий:** длинный ключ TMDB или пароль Xtream вводится с телефона, а не пультом.
- **Критерии приёмки:**
  - используется для: источника (SRC-023), ключа TMDB, входа в OpenSubtitles, картинки профиля и фона, M3U-файла и файла копии;
  - страница доступна только пока открыт соответствующий экран на ТВ; без верного PIN запросы отклоняются;
  - пришедшие данные попадают в форму на ТВ и применяются только после подтверждения на ТВ.
- **Фаза:** P6
- **Статус:** ⬜ нет

### BAK-011 Файл настроек (ранняя копия)
- **Суть:** настроенное приложение сохраняется в файл и восстанавливается из него на новом устройстве или после переустановки — без повторного ввода источника, телегида и правок каналов. Требование владельца проекта; это ранняя часть BAK-001…BAK-004, которые в P5 расширяют её, а не заменяют.
- **Сценарий:** пользователь переустанавливает приложение или ставит его на второй ТВ, выбирает «Загрузить настройки из файла» и сразу получает свой список каналов в привычном виде.
- **Поведение:** в настройках — «Сохранить настройки в файл» и «Загрузить настройки из файла»; файл выбирается системным окном, на приставках без него — сохраняется в «Загрузки» и берётся оттуда. «Загрузить из файла» есть и на экране первого запуска.
- **Критерии приёмки:**
  - в файл попадают: источник, все настройки (в том числе расписание обновления, источник логотипов), источники телегида и ручные привязки, избранное, скрытие, переименования, порядок, подборки; содержимое плейлиста, программа передач и кэш картинок не сохраняются — они загружаются заново;
  - формат — тот же `.fervo`, что в BAK-001 (ZIP с `manifest.json`: версия формата, версия приложения, дата, состав); P5 добавляет части, а не меняет формат;
  - пароль источника по умолчанию не сохраняется; отметка «Сохранить и пароль» включает его с предупреждением, что файл не зашифрован (шифрование — BAK-002); без пароля после загрузки приложение просит ввести его;
  - перед применением — подтверждение «текущие настройки будут заменены»; после применения источник и телегид сразу обновляются, правки каналов ложатся на них по устойчивому ключу канала;
  - чужой, повреждённый файл или файл более новой версии формата — понятная ошибка, текущие данные не меняются;
  - тест в `core`: сохранение → загрузка в чистую базу даёт то же состояние; повреждённый файл ничего не меняет.
- **Фаза:** P1
- **Статус:** ⬜ нет
