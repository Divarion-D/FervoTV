# P3: проверка на физическом ТВ

Дата: 03.11.2026. Проверяемая ревизия: `7e3bebf68aa4a623f3e0e99afd872333e3f8da48`.
Установлен debug APK с SHA-256
`b9e4e1c1ff92f7b6e3df809f1520ceecea9b19d4ba7d8f6ec4d20b986c809341`.

Проверяется настоящее Android TV-устройство, не телефон и не host-эмуляция `television`.
Ввод — ADB-события DPAD/OK/Back/медиаклавиш; физический ИК/Bluetooth-пульт и удержание его клавиш
этим не принимаются. Установка выполнена через mobile-device-mcp; его сервер автоматизации не
достиг готовности, поэтому запуск, ввод, снимки и UI Automator выполняются через обычный ADB.
Некоторые чтения UI/снимки прерывались: такие попытки не засчитываются как успешный тест.

## Стенд и границы

- API 25, TV-режим; система заявляет PiP, но приложение вызывает его только начиная с API 26.
- Экран сообщает единственный режим 1280×720 @ 60 Гц и пустой список HDR-возможностей.
  На этом подключении нельзя принять реальное переключение частоты/разрешения или HDR-вывод.
- Пользователь подтвердил обычный звуковой выход ТВ и слышимый тон HLS. Ресивера HDMI/ARC Dolby/DTS
  и Bluetooth-аудио в этом прогоне нет: passthrough, surround и задержки разных маршрутов не приняты.
- Набор синтетический: H.264/AAC MP4, HLS с обновляемым окном, DASH, MPEG2/MP2 TS, MKV/DTS,
  MP4 без расширения, два AAC-языка ru/en, встроенный текст TX3G, отсутствующий адрес и endpoint,
  требующий конкретные User-Agent/Referer. Содержимое и дорожки сверены `ffprobe`.
- Тестовый текст субтитров `P3 TV SUBTITLE VISIBLE` действует с 0:01 до 3:59.
  Проверяется изображение в этом интервале, а не только наличие дорожки в списке.
- HTTP-стенд изначально не поддерживал Range. После остановки длинного VOD добавлен Range;
  самопроверка: 206 / 16 байт на `bytes=0-15`, правильные заголовки принимаются, без них — 403.
  Начальная остановка без Range не считается успешным тестом таймера или доказанной поломкой декодера.
- Разрешённая резервная копия сделана при остановленном debug-приложении до подмены источника.
  Архив проверен чтением; пользовательские реквизиты не входят в этот документ.

## Найденные проблемы, не успешные проверки

- SRC-009: endpoint с обязательными заголовками вернул 403. При повторе сервер получил правильный
  `Referer`, но `User-Agent: FervoTV/0.1.0 (Android)` вместо `FervoTV-P3-Test`.
  `ExoEngine` задаёт агент фабрике через `setUserAgent`, а затем кладёт агент элемента в default properties.
  В [Media3 1.5.1](https://github.com/androidx/media/blob/1.5.1/libraries/datasource/src/main/java/androidx/media3/datasource/DefaultHttpDataSource.java#L573-L589)
  поле userAgent применяется после остальных заголовков и перезаписывает его. Старый кадр не означает успех нового потока.
- PLR-007: в VOD на паузе первый Back с кнопки оставил панель, сняв фокус; следующий скрыл панель,
  ещё один вернул в карточку. Требование «первый Back скрывает панель» на ТВ не принято.
- PLR-009: английская встроенная дорожка отмечена выбранной (`application/x-media3-cues`),
  но известный текст не появился в кадре внутри времени cue. Выбор дорожки не равен показу субтитров.
- PLR-027: пункт меняется на «Показать видео», но на паузе SurfaceView оставляет последний кадр.
  Кроме того, компактная шапка/Стоп, радио-метка и продолжение при навигации не реализованы.
- PLR-029: повторная команда `KEYCODE_MEDIA_PLAY` поставила играющий VOD на паузу.
  Отдельные Play/Pause нельзя принимать по успешному toggle Play/Pause.
- При первом открытии фильмов и первой карточки начального фокуса не было: для подготовки
  VOD использован указатель. Эти переходы нельзя выдавать за полностью пройденный пультовый маршрут.
- PLR-026: после ухода из эфира на главную общего углового окна нет. Старый HLS-сеанс заменён
  предпросмотром другого элемента (`test.ts`, новая позиция 0), что видно и по HTTP-запросам.
  Независимый Home-preview не является продолжением старого потока.
- Группа настроек «Плеер» открывается пустой: только заголовок и Back. В `SettingsScreen.kt`
  `if (group == PLAYER)` вложен в `if (group == LIBRARY)`; ветка недостижима. Изменение/сохранение
  предбуфера, громкости, языков и частоты через этот UI не принято, а не просто пропущено.
- PLR-011: реальный локальный SRT размечен приложением как WebVTT. Ошибка подтверждена логом
  парсера, не предполагается по отсутствующему тексту. Приложение осталось живым, сломалось воспроизведение.

## Артефакты и восстановление

Локальные снимки, последовательность событий, журнал только процесса debug-приложения, HTTP-журнал
и разрешённая копия находятся в `/tmp/fervo-tv-p3.sP99lC/`. `/tmp` временный; архив может содержать
реквизиты, поэтому в git не добавляется.

✅ Прогон завершён; исходные источник, настройки, история, избранное, файлы и кэш восстановлены.
Передача восстановления через stdin ADB оказалась неполной и была отвергнута контрольной проверкой.
Архив передан как отдельный файл; SHA-256 на хосте и ТВ совпал. Android tar сообщил об отказе
переноса Linux UID, поэтому дополнительно проверены реальные владельцы каталогов — UID debug-приложения.
После восстановления состав и SHA-256 всех 59 файлов совпали с исходным снимком;
`PRAGMA integrity_check` исходной и независимо считанной восстановленной SQLite — `ok`.

Только после этого удалены отложенные QA-каталоги, тестовый SRT, временный экспорт и файлы ADB на ТВ.
Состояние тестов до очистки сохранено в локальном `after-tests.tar`; исходный `before.tar` тоже сохранён.
Архивы доступны только владельцу, в git не включены. Тестовый процесс и локальные HTTP/HLS-процессы
остановлены; ориентация осталась исходной, системная громкость не изменялась. Wi-Fi ADB оставлен включённым.

Ограничения: физическое удержание ИК/Bluetooth-пульта, гарнитура/голос, реальный HDR/смена режима экрана,
HDMI/ARC passthrough и Bluetooth-задержки не приняты. Для DRM нет подходящего лицензионного стенда;
для отсутствующих DSP/движков/стилей/сдвигов/сбросов нет реализованного сценария, который можно закрыть
проверкой ТВ. Неисправные сценарии записаны выше, а не отмечены как успешные.

Изменения этого прогона — документация и статусы; код приложения не исправлялся, нового коммита/push нет.
